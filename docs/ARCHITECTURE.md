# Grid Table 架构设计

## 整体架构

Grid Table 采用模块化设计，将表格的不同功能拆分为独立的管理器，通过核心的 Grid 类进行协调。这种设计使得代码结构清晰，便于维护和扩展。

```
┌─────────────────────────────────────────────────────────────────┐
│                            Grid                                 │
├─────────────┬─────────────┬────────────────┬───────────────────┤
│ VirtualDOM  │ Component   │ Event          │ ScrollSync        │
│ Manager     │ Manager     │ Manager        │ Manager           │
└─────────────┴─────────────┴────────────────┴───────────────────┘
```

## 核心模块

### Grid

Grid 是表格的主类，负责协调各个管理器和提供对外API。它管理表格的生命周期，处理数据和配置，并将渲染任务委托给 VirtualDOMManager。

主要职责：
- 初始化各个管理器
- 处理用户配置和数据
- 提供对外API
- 协调各个管理器之间的交互
- 管理行节点和数据模型

### VirtualDOMManager

VirtualDOMManager 负责高效地创建和更新DOM结构。它实现了虚拟滚动技术，只渲染可见区域的行和列，大大提高了表格在处理大量数据时的性能。

主要职责：
- 创建和更新虚拟DOM结构
- 实现虚拟滚动
- 管理DOM元素的复用
- 优化渲染性能

### ComponentManager

ComponentManager 负责管理和渲染自定义组件。它支持两种组件类型：函数组件和类组件，并提供了组件的注册、实例化和生命周期管理。

主要职责：
- 注册自定义组件
- 创建组件实例
- 管理组件生命周期
- 处理组件的视图和编辑模式

### EventManager

EventManager 负责处理表格内的各种事件。它提供了事件的注册、触发和移除功能，使得表格的各个部分可以通过事件进行通信。

主要职责：
- 注册事件监听器
- 触发事件
- 移除事件监听器
- 处理事件冒泡和捕获

### ScrollSyncManager

ScrollSyncManager 负责处理表头和表体的滚动同步。它确保在水平滚动时，表头和表体保持同步，提供一致的用户体验。

主要职责：
- 同步表头和表体的滚动
- 处理滚动事件
- 优化滚动性能

## 数据流

Grid Table 的数据流遵循单向数据流原则，从数据源到视图的流动清晰可追踪。

1. 用户提供初始数据和配置
2. Grid 初始化数据模型和各个管理器
3. 数据经过排序、过滤等处理
4. VirtualDOMManager 根据处理后的数据创建虚拟DOM
5. 组件被渲染到DOM中
6. 用户交互触发事件
7. 事件处理器更新数据模型
8. 数据变化触发视图更新

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  用户输入 │───>│ 数据处理  │───>│ 虚拟DOM  │───>│  渲染    │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
      ^                                               │
      │                                               │
      └───────────────────────────────────────────────┘
                          事件
```

## 渲染流程

1. **初始渲染**：
   - Grid 解析配置和数据
   - 创建行节点模型
   - VirtualDOMManager 创建初始DOM结构
   - 计算可视区域
   - 渲染可视行和列

2. **滚动更新**：
   - 监听滚动事件
   - 计算新的可视区域
   - 复用已有DOM元素
   - 更新行和列的内容
   - 应用样式和事件

3. **数据更新**：
   - 接收新数据
   - 更新行节点模型
   - 触发视图刷新
   - VirtualDOMManager 更新DOM结构

## 组件系统

Grid Table 提供了灵活的组件系统，支持自定义单元格的渲染和编辑。

### 组件类型

1. **函数组件**：
   - 简单的函数，接收参数并返回DOM元素
   - 适合简单的渲染逻辑
   - 无状态，每次渲染都会重新创建

2. **类组件**：
   - 具有生命周期方法的类
   - 支持状态管理
   - 可以实现复杂的交互逻辑

### 组件注册

组件通过 ComponentManager 进行注册，每个组件可以有两种模式：

- **视图模式（view）**：用于展示数据
- **编辑模式（edit）**：用于编辑数据

### 组件参数

组件接收以下参数：

- **value**：单元格的值
- **data**：行数据
- **rowIndex**：行索引
- **column**：列定义
- **api**：Grid API
- **props**：组件特定的属性
- **onComplete**：编辑完成回调
- **onCancel**：取消编辑回调

## 单元格合并

Grid Table 支持行合并和列合并，实现方式如下：

1. **计算合并信息**：
   - 在渲染前计算每个单元格的合并信息
   - 创建合并单元格的映射表

2. **渲染合并单元格**：
   - 合并单元格扩展尺寸覆盖合并区域
   - 被合并的单元格设置为隐藏

3. **处理事件**：
   - 合并单元格代理被合并单元格的事件
   - 确保编辑和选择等功能正常工作

## 树形结构

树形结构的实现基于以下设计：

1. **数据模型**：
   - 使用父子关系表示层级结构
   - 每个节点包含 children 数组

2. **渲染**：
   - 计算节点的层级和缩进
   - 渲染展开/折叠图标
   - 处理节点的可见性

3. **交互**：
   - 处理展开/折叠事件
   - 更新节点的展开状态
   - 刷新视图显示/隐藏子节点

## 性能优化

Grid Table 采用多种技术优化性能：

1. **虚拟滚动**：
   - 只渲染可视区域的行和列
   - 复用DOM元素减少创建和销毁

2. **批量更新**：
   - 收集多个更新操作，一次性应用
   - 减少DOM重排和重绘

3. **延迟渲染**：
   - 复杂组件延迟渲染
   - 使用 requestAnimationFrame 优化动画

4. **事件委托**：
   - 在容器级别处理事件
   - 减少事件监听器数量

## 扩展点

Grid Table 设计了多个扩展点，便于用户自定义功能：

1. **自定义组件**：
   - 注册自定义视图和编辑组件
   - 通过 props 配置组件行为

2. **自定义渲染器**：
   - 使用 cellRenderer 自定义单元格渲染
   - 支持函数和对象两种方式

3. **事件回调**：
   - 提供丰富的事件回调
   - 用户可以监听和处理各种表格事件

4. **样式定制**：
   - 通过 CSS 变量自定义样式
   - 支持条件样式和主题切换
